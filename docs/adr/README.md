# Architecture Decision Records

팀이 함께 내린 기술·설계 결정을 기록한다. **왜 그렇게 정했는지**를 남기는 것이
목적이다. 발표 Q&A에서 "왜 이 기술을 골랐나요"라는 질문이 반드시 나오고,
루브릭의 **"설계 타당성"** 이 이것을 본다.

## 무엇을 ADR로 남기는가

3일짜리 프로젝트다. 모든 것을 기록하면 시간이 모자란다. **되돌리기 어렵고
팀 전체에 영향을 주는 결정**만 남긴다.

| 남긴다 | 남기지 않는다 |
| --- | --- |
| 백엔드 스택 선택 | 변수 이름, 폴더 이름 |
| 데이터베이스 제품 선택 | 라이브러리 버전 |
| Mock API를 어디에 둘지 | 컴포넌트 분리 방식 |
| AI 확장 지점을 어디에 둘지 | CSS 프레임워크 |

목표는 **3~5개**다. 그 이상이면 과하다.

## 쓰는 방법

1. 결정이 필요하면 `type:decision` Issue로 논의한다. (Issue 템플릿 있음)
2. 합의되면 `template.md`를 복사해 `NNNN-short-title.md`로 만든다.
3. 번호는 `0001`부터 순서대로. 아래 목록에 한 줄 추가한다.
4. 이전 결정을 뒤집을 때 **기존 문서를 지우지 않는다.** 새 ADR에서
   "ADR NNNN을 대체함"이라고 적고, 기존 문서의 상태를 `Superseded`로 바꾼다.

## 상태

| 상태 | 뜻 |
| --- | --- |
| `Proposed` | 논의 중. 아직 확정 아님 |
| `Accepted` | 확정. 이대로 진행 |
| `Superseded` | 다른 ADR로 대체됨 |
