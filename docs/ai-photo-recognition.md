# 사진 인식 AI — 발표 정리

> **발표 2번 섹션(2분)** *"서비스 내 AI 확장 지점 소개, 프롬프트 설계 내용 및 입출력 JSON 스키마 구조"* 와
> **5번 섹션** *"한계점 및 추후 AI 실제 결합 시 로드맵"* 에서 쓴다.
>
> 정본은 [`07-ai-ready.md`](07-ai-ready.md)다. 이 문서는 **발표에서 말할 순서대로** 추린 요약이고,
> 숫자와 결과는 전부 실제로 돌려서 나온 것이다.

## 한 장으로 말하면

**짐 사진을 올리면 AI가 물품을 알아보고 내 체크리스트에 자동으로 올린다.**

- 설계만 한 것이 아니라 **실제로 동작한다.** 데모 사진 2장에서 물품 12개를 인식했다.
- 그런데 **기본값은 Mock이다.** 발표 시연은 Mock으로 돌린다 — 네트워크·요금·응답 시간에
  시연이 묶이면 안 된다. 실제 호출은 `.env` **한 줄**을 바꿔야만 나간다.
- 그 한 줄이 이 프로젝트의 주제다. **"AI가 들어올 자리를 정확히 비워 뒀는가"** 를
  말로 주장하지 않고 실제로 갈아 끼워서 보인다.

## 1. 왜 하필 여기에 AI를 뒀나

> 채점 기준 — *"AI 확장 지점 정의의 타당성"* · Peer Review — *"확장 지점이 서비스 흐름상 타당한가?"*

[`01-service-plan.md`](01-service-plan.md)가 세운 기준은 이거다.

> **"AI를 빼도 서비스가 돌아가되, 고통스럽게 돌아간다."**

사진에서 무엇이 있는지 알아보는 일은 **규칙으로는 아예 불가능하다.** 이 서비스의 약속인
*"사진만 찍으면 알려준다"* 가 여기서 시작한다. AI가 없으면 사용자가 목록을 손으로 친다.

**설득력은 반대쪽에서 나온다.** 우리는 AI를 두지 **않은** 곳도 같은 기준으로 정했다.

| 자리 | AI인가 | 왜 |
| --- | --- | --- |
| 사진에서 물품 찾기 | **AI** | 규칙으로 불가능하다 |
| 여행 조건에서 빠진 것 떠올리기 | **AI** | 경우의 수가 무한하다 |
| 반입 규정 판정 | 규칙 엔진 | `transport_rules` 를 보면 정확히 풀린다 |
| 무게 합산·완료율 | 산식 | 더하기다. AI를 두면 **틀릴 자리만 늘어난다** |

> 발표에서 이 표를 보여주면 *"AI를 아무 데나 붙이지 않았다"* 가 한 번에 전달된다.

## 2. 어떻게 도나

```
사용자          사진 업로드
   │            POST /api/trips/{tripId}/photos
   ▼
[BE]            POST /api/ai-jobs  { jobType: BAG_CHECK, tripId }
   │            ──▶ 202 Accepted + jobId          ← 여기서 응답이 끝난다
   │
   │  (백그라운드)  사진 파일 읽기 → 1024px JPEG 로 축소 → 모델 호출
   │                → detected_objects 저장
   │                → 내 체크리스트에 PREPARED 로 자동 등록
   │                → 두 저장이 끝난 뒤에만 COMPLETED
   ▼
화면            GET /api/ai-jobs/{jobId} 폴링 → COMPLETED 면 결과 표시 (S-04)
```

**왜 즉시 응답하지 않고 `202` + 폴링인가.** 실제 모델은 십수 초가 걸린다. 요청 하나를
그만큼 붙잡고 있으면 화면이 멈춘다. **Mock이 즉시 답할 수 있어도 이 구조를 지켰다** —
그래야 실제 모델로 바꿀 때 프런트엔드를 고치지 않는다. 실제로 고치지 않았다.

**저장이 먼저, 완료 표시가 나중이다.** 순서를 뒤집으면 화면이 "완료" 를 보고 조회했는데
목록이 비어 있는 순간이 생긴다. 저장이 실패하면 전체가 롤백되고 작업은 실패로 남는다 —
**거짓 완료를 만들지 않는다.**

## 3. 입출력 JSON 스키마

> 채점 기준 — *"입출력 JSON 스키마 타당성"* · Peer Review — *"기존 웹 구조와 호환되는가?"*

### 입력 — 사진 파일이 없다

```json
{ "photoIds": [12, 13] }
```

**사진을 요청 본문에 넣지 않는다.** 백엔드가 `photoIds` 로 `trip_photos.file_path` 를 읽어
모델에 이미지로 넘긴다. 그래서 `ai_jobs.input_payload` 에는 **id만 남고**, 같은 작업을
다시 볼 때 수백 MB짜리 base64를 다시 읽지 않아도 된다.

### 출력 — 한 항목이 DB 한 행

```json
{
  "detections": [
    { "photoId": 13, "name": "태블릿", "qty": 1, "confidence": 0.9,
      "confidenceLevel": "HIGH", "missingInfo": "배터리 정격(Wh)", "labelText": null }
  ],
  "failedPhotoIds": []
}
```

`detections[]` 한 항목이 `detected_objects` **한 행과 1:1**이다. `missingInfo` · `labelText` 도
`missing_info` · `label_text` 컬럼에 그대로 들어간다. 변환 계층이 없다는 뜻이고,
**AI 응답 스키마를 DB 스키마와 같은 모양으로 설계했다**는 뜻이다.

### 누가 채우나 — 경계가 분명하다

| 누가 | 무엇을 |
| --- | --- |
| **모델** | `photoId` `name` `qty` `confidence` `missingInfo` `labelText` |
| **서버** | `confidenceLevel`(≥0.80 HIGH · ≥0.50 MEDIUM · 그 외 LOW) · `failedPhotoIds` |

**서버 몫은 모델에게 묻지도 않는다.** 모델용 스키마에서 아예 빼 버렸다. 물어보면
경계값이 흔들리고, 실패한 사진은 애초에 모델이 보지 못했다.

## 4. 프롬프트를 이렇게 쓴 이유

> 채점 기준 — *"프롬프트 설계 타당성"*

원문은 [`07-ai-ready.md`](07-ai-ready.md#system-prompt)에 있다. 발표에서는 **규칙 6개 중
셋만** 짚으면 충분하다.

| 규칙 | 왜 넣었나 |
| --- | --- |
| **1. 보이지 않는 속성은 추정하지 않는다.** 필요하면 `missingInfo` 에 무엇이 필요한지 적는다 | 반입 판정에는 용량(ml)·배터리 정격(Wh)·날 길이(cm)가 필요한데, **사진에는 안 보인다.** 모델이 지어내면 그 값으로 "기내 반입 가능" 을 판정하게 된다. **수치 확정은 사용자가 한다** |
| **2. 확신이 없으면 이름을 지어내지 말고 보이는 대로 적는다** (예: `"검정 파우치"`) | 억지로 이름을 붙이면 사용자가 목록에서 그게 뭔지 못 찾는다. 신뢰도를 낮춰 화면이 "확인 필요" 로 묶는다 |
| **3. 브랜드명은 `name` 이 아니라 `labelText` 에** | `name` 은 품목 마스터(`item_weights`)와 이름으로 맞춰야 한다. "다이슨 에어랩" 은 안 맞지만 "고데기" 는 맞는다 |

**규칙 1이 실제로 지켜졌다.** 데모 사진에서 모델이 낸 `missingInfo` 는 딱 둘이었다.

| 물품 | `missingInfo` |
| --- | --- |
| 태블릿 | `배터리 정격(Wh)` |
| 튜브형 화장품 | `용량(ml)` |

청바지·샌들·셔츠·모자·여권에는 붙지 않았다. **반입 규정이 걸리는 물건에만 붙었다.**

## 5. 모델이 낸 답을 그대로 믿지 않는다

**설계에서 가장 설명할 가치가 있는 부분이다.** 우리는 OpenAI의 Structured Outputs(`strict`)를 써서
모델이 스키마를 벗어난 모양으로 답할 수 없게 막았다. 그런데 —

> **`strict` 가 지켜 주는 것은 *모양* 뿐이다.**
> `qty: 500`, `confidence: 1.9`, 보내지도 않은 `photoId` 는 **스키마를 그대로 통과한다.**

그대로 저장하면 `NUMERIC(4,3)` 컬럼이나 FK에서 터진다. 그래서 서버가 한 번 더 본다.

| 서버가 다시 검사하는 것 | 위반 시 |
| --- | --- |
| `photoId` 가 이번에 보낸 사진인가 | 그 인식 결과를 버린다 |
| `name` 이 공백뿐인가 | 항목을 만들지 않는다 |
| `qty` 가 1~99인가 | 잘라 낸다 |
| `confidence` 가 0~1, 소수 셋째 자리인가 | 자르고 반올림한다 |
| 사진 한 장에 10개, 전체 100개 | 신뢰도 높은 순으로 남긴다 |

이 다섯 가지는 [`OpenAiBagCheckTest`](../backend/src/test/java/com/skala/miniai/domain/OpenAiBagCheckTest.java)가
테스트로 잡고 있다. **프롬프트로 부탁한 것과 서버가 보장하는 것을 구분했다**는 게 요지다.

## 6. 환경 변수 한 줄로 켜고 끈다 — 핵심 슬라이드

```bash
# backend/.env
AI_PROVIDER=openai
AI_API_KEY=          # 로컬에서만 실제 키 입력
AI_MODEL=gpt-4o-mini
AI_BASE_URL=https://api.openai.com/v1
```

| 계층 | 실제 AI를 붙이면 |
| --- | --- |
| Frontend | **변경 없음** — 같은 엔드포인트, 같은 응답 스키마 |
| REST API 규격 | **변경 없음** — [`06-api-spec.md`](06-api-spec.md) 계약 그대로 |
| DB 스키마 | **변경 없음** — `ai_jobs.output_payload`(jsonb)에 그대로 |
| `AiClient` 인터페이스 | **변경 없음** (사진 인식 기준) |
| `AiJobService` · 엔티티 · DTO · 컨트롤러 | **변경 없음** |
| Backend 내부 | **여기만** — `MockAiClient` 옆에 `OpenAiClient` 를 두고 `@Primary` 로 밀어낸다 |

사진 인식을 붙이면서 손댄 것은 **새 파일 넷이 전부**다. 기존 파일은 하나도 고치지 않았다.

| 새 파일 | 하는 일 |
| --- | --- |
| `OpenAiClient` | `AiClient` 구현. 응답 검증·보정·재시도 1회 |
| `OpenAiChatApi` | HTTP 한 곳. **SDK를 넣지 않고** `RestClient` 로 직접 부른다 |
| `BagCheckPrompt` | 프롬프트 원문 + 모델용 파생 스키마 |
| `VisionImageLoader` | 사진을 줄여 `data:` URL 로. 못 읽으면 `failedPhotoIds` |

> **정확히 말하면 — 준비물 추천과 작업별 모델명 기록까지 붙일 때는 기존 파일 두 곳이 바뀌었다.**
> `AiClient` 에 `run(jobType, **tripId**, input)` 오버로드를 더하고 `AiJobRunner` 가 그쪽을
> 부르도록 고쳤다. 혼합 모드 사용 이력을 위해 `modelName(jobType, tripId)`도 추가했다.
> 07의 input에는 `tripId` 가 없는데(서버가 아는 값이라 스키마에
> 넣지 않았다), 중복 제거를 하려면 **미완료 항목까지 포함한 내 목록**을 읽어야 해서다.
> **기본 구현이 `tripId` 를 버리고 기존 메서드로 넘기므로 `MockAiClient` 는 그대로다.**
> 질문이 나오면 이렇게 답하는 편이 낫다 — 커밋을 열면 보이는 사실이다.

### 제공자 주소

`AI_BASE_URL` 이 어디로 나갈지 정한다. **`openai` 는 회사 이름이 아니라 프로토콜 이름이다.**

```bash
AI_BASE_URL=https://api.openai.com/v1                            # OpenAI
AI_BASE_URL=https://generativelanguage.googleapis.com/v1beta/openai   # Gemini (무료 티어)
```

현재 OpenAI 키 시연 설정은 첫 번째 주소를 쓴다. 아래 Gemini 결과는 2026-09-03의 과거 검증 기록이다.

### Mock ↔ 실제, 무엇이 다른가

| | `mock` | `openai` |
| --- | --- | --- |
| 인식 결과 | **사진을 보지 않는다.** 고정 8개가 나온다 | 진짜 사진을 본다 |
| 응답 시간 | 즉시 | 십수 초 |
| 실패 | 사실상 없음 | 429·5xx·타임아웃은 1회 재시도 후 `FAILED`, 401·400은 즉시 `FAILED` |
| 비용·네트워크 | 없음 | 나간다 |
| **`202` → 폴링 · DB 저장 · 자동 등록 · 화면** | **완전히 동일** | **완전히 동일** |

## 7. 실제로 돌린 결과

저장소에 커밋해 둔 데모 사진 2장([`database/demo-photos/`](../database/demo-photos))으로 실행했다.

```bash
cd backend && ./gradlew test --tests '*RealOpenAiSmokeTest*' -Dai.smoke=true
```

> `-Dai.smoke=true` 가 없으면 건너뛴다. 팀원이 `./gradlew build` 를 돌릴 때마다
> 요금이 나가면 안 된다.

**사진 2장 → 물품 12개, 실패 0장.**

| 사진 | 인식된 물품 |
| --- | --- |
| 1 | 청바지 · 샌들 ×2 · 셔츠 ×3 · 초록색 지갑 · 바지 |
| 2 | 모자 · 여권 · 노란색 파우치 · 카메라 · 태블릿 · 의류 ×7 · 튜브형 화장품 |

- 전부 입력에 있는 `photoId`, `qty` 1~99, `confidence` 0~1을 지켰다.
- 이름을 못 붙일 물건은 **지어내지 않고** "노란색 파우치" 라고 적었다 (규칙 2).
- 반입 규정이 걸리는 둘에만 `missingInfo` 가 붙었다 (규칙 1).

### 같은 자리에 하나 더

준비물 추천(`PACKING_LIST`)도 같은 구조로 붙였다. 도쿄 3박4일 입력에 **Open-Meteo 날씨**
(API 키 불필요)를 더해 부른다.

| | 후보 수 | 나온 것 |
| --- | --- | --- |
| 날씨 없이 | 5개 | 여권 · 엔화 현금 · 보조배터리 · 운동화 · 상비약 |
| 날씨 붙이고 | **10개** | 위 + **경량 패딩 · 긴팔 셔츠** — 계절 평균 *최저 12도·최고 25도* 를 그대로 인용했다 |

이미 챙긴 충전기와 **아직 미완료인** 우산을 다시 추천하지 않았다.

## 8. 한계와 다음 — 발표 5번 섹션

**정직하게 적는다.** 아는 한계를 먼저 말하는 쪽이 신뢰를 얻는다.

| 한계 | 내용 |
| --- | --- |
| **정확도를 잰 것이 아니다** | 사진 2장·입력 1건을 돌려 본 것이다. 인식률·오탐률은 재지 않았다. `confidenceLevel` 경계값(0.80 / 0.50)도 초기값이다 |
| **앱 전 구간은 미검증** | 팀 Supabase 자격 증명 문제로 `bootRun` 이 뜨지 않았다. 저장 경로 자체는 H2로 도는 테스트가 확인한다 |
| **OpenAI 경로는 미확인** | Gemini 호환 엔드포인트로만 돌렸다 |
| **느린 호출이 DB 커넥션을 쥔다** | 응답을 기다리는 동안 커넥션 하나가 묶인다. 풀이 5라 동시 5명이면 여섯 번째가 밀린다. Mock에서는 드러나지 않던 문제다 |
| **사진 간 동일 물품 병합** | 지금은 이름이 같으면 **수량을 합치지 않고 큰 값**을 쓴다. 사진 두 장에 같은 셔츠가 찍혔다고 두 벌은 아니다 |

| 다음 | 왜 |
| --- | --- |
| 작업 실행에 큐(메시지 브로커) 도입 | 위 커넥션 문제를 푼다. **FE의 폴링 계약은 그대로 둔다** |
| 인식 정확도 측정 · 경계값 조정 | 사후 수정률을 보고 정한다 |
| `ai_jobs` 에 토큰 수 컬럼 | 비용 모니터링 |

## 발표 때 이 순서로 (2분)

1. **"사진만 찍으면 알려준다"** — 이 약속이 AI 없이는 성립하지 않는다 (§1)
2. **AI를 두지 않은 곳** 을 같은 기준으로 정했다 (§1 표) ← 여기서 신뢰를 얻는다
3. **입력에 사진 파일이 없다** · **출력 한 항목 = DB 한 행** (§3)
4. **`strict` 가 지켜 주는 건 모양뿐이라 서버가 다시 검사한다** (§5)
5. **`.env` 한 줄** 로 Mock ↔ 실제가 갈리고, 나머지 계층은 안 바뀐다 (§6)
6. 실제 결과 — **`missingInfo` 가 태블릿과 화장품에만 붙었다** (§7)
